How I work

The same loop, whatever the tool.

Find the real problem

I start in the data and with the user, not the feature request. Most of the work is figuring out what is actually worth building before writing a line of it.

Frame it clearly

I turn a fuzzy ask into a sharp problem statement, a hypothesis, and a way to measure whether it worked. If I cannot measure it, I have not framed it yet.

Then build

I ship the thing, watch how people use it, and change it. I would rather have a rough product in real hands than a perfect plan in a doc.
